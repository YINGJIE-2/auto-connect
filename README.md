## 专门适配苏州城市学院

**这不是一个通用脚本，是针对苏州城市学院（原苏州大学文正学院）校园网一点点实测出来的。**
协议参数、运营商后缀、错误码含义，全部来自对**本校网关**的逆向与真机验证。

### 本校网络环境（实测记录）

| 项 | 实际情况 |
|---|---|
| 网关厂商 | **Dr.COM 城市热点**（`Server: DrcomServer1.0`） |
| 认证页地址 | `http://172.16.8.22/` |
| 认证接口 | `http://172.16.8.22:801/eportal/`（JSONP，**801 端口**） |
| 系统代号 | `WZXY`（文正学院） |
| 接入方式 | 宿舍**有线网**（插网线），DHCP 自动分配 IP |
| 运营商后缀 | 中国电信 `@telecom` · 中国移动 `@cmcc` · 中国联通 `@unicom` · 校园内网 无后缀 |
| 密码传输 | 网关要求**明文**提交（`enMd5=0`）—— 所以本程序用 Windows DPAPI 在本地加密保存 |
| 图形验证码 | 密码正确时**不触发**；连续输错才会弹 → 程序因此主动降低失败重试频率，避免把你的账号刷到弹码 |
| 实测状态 | ✅ 2026-10-10 端到端通过：开机自启 / 掉线自动重连 / 手动重连 |

## 使用教程

### 第 0 步 · 先确认你能不能用（10 秒）

**苏州城市学院的同学 → 直接跳到第 1 步**，本工具就是为本校网关做的，已实测通过。

其他学校的同学，先确认网关是不是 Dr.COM：未登录状态下打开一个 **http** 网站
（比如 `http://www.baidu.com`），会自动跳到学校的认证页。在那个页面按 `Ctrl+U` 看源码，
或看资源路径里有没有 **Dr.COM**、**城市热点**、**DrcomServer** 字样。

| 你的学校网关 | 能用吗 |
|---|---|
| Dr.COM / 城市热点 | ✅ 直接可用 |
| 深澜 / 锐捷 / H3C / 华为 | ❌ 需要自己加适配器，见[适配其他学校](#适配其他学校) |
| 不确定 | 直接跳到第 3 步试，程序会明确告诉你结果 |

**系统要求**：Windows 10 / 11（64 位）。**不需要**装 Python、Java 或任何运行环境。

---

### 第 1 步 · 下载

到本仓库的 **[Releases](../../releases)** 页面，下载 `auto-connect.exe`。

> ⚠️ **不要用 `git clone` 拿 exe** —— 仓库里只有源码，二进制文件不进 Git。
> exe 由 GitHub Actions 在发布版本时自动编译，只出现在 Releases 页面。
> 如果 Releases 页面是空的，说明作者还没发布过版本（见[常见问题](#常见问题)）。

拿到的是一个**单文件**，约 6 MB，不需要安装、不需要解压。

---

### 第 2 步 · 放到一个固定的目录

新建一个固定目录把 exe 放进去，例如：

```
D:\Tools\auto-connect\auto-connect.exe
```

> ⚠️ **别放在桌面或「下载」文件夹** —— 那些目录里的文件经常被移动或清理，
> 一旦 exe 换了位置，开机自启就会失效（自启记录的是 exe 的完整路径）。

---

### 第 3 步 · 双击运行，填三样东西

**第一次**双击 exe，会自动带你配置一遍，照着填就行：

```
  auto-connect · 校园网自动认证
  开箱即用：填一次学号密码，以后开机自动联网、掉线自动重连。
-----------------------------------------------------------
学号: 2023001234
密码（输入时不显示）:          ← 敲键盘不会有任何显示，这是正常的，敲完直接回车
再输一次确认:

你在认证页第一个下拉框里选的是哪个？
  1) 中国电信
  2) 中国移动
  3) 中国联通
  4) 校园内网
请输入编号 [1]: 2

[1/3] 配置已保存
[2/3] 正在测试认证 ... 认证成功！
[3/3] 注册开机自启 ... 已注册。
```

三个输入项怎么填：

| 输入项 | 填什么 | 注意 |
|---|---|---|
| **学号** | 你平时登录用的那个 | 一般就是纯学号，不用带 `@` 后缀 |
| **密码** | 你平时登录用的密码 | **输入时不显示**是正常现象（安全设计），不是卡住了 |
| **运营商** | 看认证页第一个下拉框，你平时选哪个就填对应编号 | 填错会认证失败，但认证成功页会提示，可以改 |

最后一段 `[3/3]` 是注册开机自启。看到它就说明装好了。

---

### 第 4 步 · 确认装好了

配完之后再双击 exe（或者刚才那个窗口按回车关掉、重新双击），会看到**操作菜单**：

```
===========================================================
  账号     : 2023001234@cmcc（中国移动）
  当前状态 : 已联网
  后台守护 : 运行中              ← 要是显示"未运行"，输入 3 回车
  开机自启 : 已开启（任务计划）   ← 要是显示"未开启"，输入 5 回车
-----------------------------------------------------------
  1) 立即检测并重连
  2) 修改配置（学号 / 密码 / 运营商）
  3) 启动后台守护（关掉本窗口也会继续跑）
  4) 停止后台守护
  5) 开机自启  开启 / 关闭
  6) 查看日志
  0) 退出
-----------------------------------------------------------
  提示：已全部就绪，以后开机不用管它。
```

**看到「后台守护：运行中」+「开机自启：已开启」这两行，就彻底完事了。**

> **这个黑色窗口只是个遥控器，随时可以关掉。**
> 真正干活的是「后台守护」，它是独立进程，关掉这个窗口照样跑。

### 完成。日常完全不用管它

从此以后：

- 开机 → 自动联网，不用你动手
- 掉线 → 最多 30 秒内自动重连
- 不需要打开这个程序，也不需要它留在后台的窗口

### 怎么确认它真的在工作

两种办法，任选：

1. **最直观**：去学校认证页点一次「**退出**」，然后什么都不做 —— 最多 30 秒它应该自动帮你登回来。
2. **看日志**：双击 exe → 输入 `6` 回车，能看到最近的运行记录，长这样：

```
2026/10/10 17:51:19 检测到未认证 (HTTP 200)，开始认证 ...
2026/10/10 17:51:19 认证成功（用时 0.1 秒），正在确认放行 ...
2026/10/10 17:51:29 在线 (HTTP 200，captive.apple.com)
```

## 菜单里每一项是干什么的

| 选项 | 作用 | 什么时候用 |
|---|---|---|
| **1) 立即检测并重连** | 立刻探一次，掉线就马上登 | 刚开机、发现没网了想手动催一下 |
| **2) 修改配置** | 改学号 / 密码 / 运营商 | 改了密码、换了运营商、打错字了 |
| **3) 启动后台守护** | 开始后台盯着网络 | **正常使用时选这个**（配置完通常已经自动开了） |
| **4) 停止后台守护** | 停止盯梢，不再自动重连 | 想临时彻底关掉它的联网行为 |
| **5) 开机自启 开启/关闭** | 控制开机是否自动启动 | 一般保持「开启」 |
| **6) 查看日志** | 看最近的运行记录 | 排查"它到底干活了没有" |
| **0) 退出** | 只关窗口，不影响守护 | 平时直接点右上角 × 也一样 |

## 常见问题

**Q：Releases 页面是空的 / 找不到 exe？**

这个仓库**只放源码，不放 exe**（二进制文件不进 Git）。exe 由 GitHub Actions 在作者发布版本时自动编译并挂到 Releases 页面。如果 Releases 是空的，你可以：

1. 到仓库的 **Actions** 标签页，找最近一次成功的 `build`，在页面底部的 **Artifacts** 里下载（得到一个 zip，解压出来就是 exe）；
2. 或者自己编译 —— 见[开发](#开发)，只需要装一个 Go，跑一条命令。

**Q：提示「账号或密码不对」怎么办？**

先去浏览器手动登录一次确认密码。注意：**密码连续输错会触发图形验证码**，所以本程序在连续失败后会主动降低重试频率（每 5 分钟一次），避免把你的账号刷到弹验证码。

**Q：会不会让我的密码泄露？**

不会。密码用 Windows 的 DPAPI 接口加密，密钥由系统根据你的 Windows 登录凭据派生，**绑定当前机器 + 当前 Windows 账号**。把 `cred.bin` 复制到别的电脑上根本解不开。配置文件和日志里都不含密码。

**Q：为什么不用 ping 判断有没有网？**

因为校园网网关不封 ping。未认证时 `ping www.baidu.com` 照样能通，看不出问题。本程序用的是系统判断「是否需要登录 WiFi」的同一套标准探测方法。

**Q：点「开机自启」时报错怎么办？**

程序有两条通道，会自动切换，菜单里的「开机自启」一行会告诉你实际用的是哪种：

| 显示 | 含义 |
|---|---|
| 已开启（任务计划） | 首选。能延迟启动、等网络就绪、崩溃自动重启 |
| 已开启（注册表启动项） | 降级。任务计划被安全软件/组策略挡住时自动走这条，兼容性更好 |
| 未开启 | 两条都失败了，报错原文会直接显示出来（含系统返回的中文原因） |

如果两条都失败，通常是把程序放在权限受限的目录里 —— 挪到 `D:\Tools\auto-connect\` 这类固定目录再试。

**Q：那个黑色窗口能关掉吗？**

能。它是操作菜单，不是守护进程本体。「后台守护」是菜单启动的独立后台进程，关掉窗口照样跑。你可以在菜单里看到「后台守护：运行中 / 未运行」来确认。

**Q：掉线后多久会自动连上？**

取决于两个因素：**发现掉线**最多 30 秒（探测间隔），加上**网关自己的会话切换时间**（实测约 5~10 秒，这段时间网关不回应任何请求，不是程序能优化的）。认证请求本身只要 0.1 秒。

**Q：杀毒软件报警？**

Go 编译的、未做代码签名的 exe 偶尔会被误报。本项目完全开源，你可以自行 `go build` 一份。

## 工作原理

校园网 Portal 认证的本质是：**浏览器向网关提交了一次 HTTP 请求**。我们把这次请求用程序复现出来即可。

```
① 插网线 → DHCP 分配 IP（这一步不需要认证）
        ↓
② 发一个 HTTP 探测请求（captive portal 标准地址）
        ↓
   已认证？ ── 返回 204 ──→ 什么都不做，继续待机
        │
        └─ 被拦截 ──→ 从 302 重定向里解析出动态参数
                ↓
③ 请求网关的认证接口，提交学号 + 密码
        ↓
④ 解析返回 JSON，判断是否成功
```

关键点：
- **只有 http 会被网关劫持**，https 不会 —— 所以探测必须用 http。
- 认证参数（如本机内网 IP）**每次都从 302 重定向里实时解析**，绝不硬编码。
- 认证成功后网关放行有 1~2 秒延迟，**复检必须重试**。

详细协议分析见 [`docs/协议分析.md`](docs/协议分析.md)。

## 命令一览

日常用菜单就够了，这些是给脚本或高级用法准备的。**所有命令都不需要管理员权限。**

| 命令 | 作用 |
|---|---|
| `auto-connect` | **双击运行**：打开操作菜单（未配置则先走配置向导） |
| `auto-connect setup` | 重新配置（改密码、换运营商） |
| `auto-connect daemon` | 在当前窗口里常驻守护（**关掉窗口就停**，一般用菜单的 3) 代替） |
| `auto-connect daemon --hidden` | 无窗口守护（开机自启用这个） |
| `auto-connect daemon --delay 30` | 延迟 30 秒再开工，并等网卡拿到 IP（注册表自启通道用） |
| `auto-connect status` | 查看当前联网状态、账号、自启状态 |
| `auto-connect login` | 立刻认证一次（不等守护周期） |
| `auto-connect log` | 显示日志文件路径 |
| `auto-connect install` | 注册开机自启 |
| `auto-connect uninstall` | 取消开机自启（想彻底卸载时用） |
| `auto-connect version` | 显示版本号 |

### 适配其他学校

核心抽象在 `internal/portal/portal.go`：

```go
type Adapter interface {
    Name() string
    Detect(portalBody []byte) bool
    Login(ctx context.Context, env Env) (Result, error)
}
```

新增一个网关只需要：
1. 在 `internal/portal/` 下新建目录，实现上面三个方法；
2. 在 `internal/app/app.go` 的 `adapter()` 里注册；
3. 主流程零改动。

**逆向思路**：多数 Portal 的认证逻辑都写在前端 JS 里（因为要由浏览器提交），把网关首页引用的 JS 读一遍，参数就全暴露了，不需要抓包。参考 [`docs/协议分析.md`](docs/协议分析.md) 里记录的过程。

## 数据与隐私

### 程序本体里没有你的任何信息

**`auto-connect.exe` 是纯程序，不含账号、密码或任何个人数据。** 所有与你相关的东西都在
`%APPDATA%\auto-connect\` 这个目录里，不在 exe 里，也不在仓库里：

| 文件 | 内容 | 能不能给别人 |
|---|---|---|
| `config.json` | 学号、运营商、网关参数 | 含你的**学号**（但不含密码）。一般没必要给，同学自己配一次更快 |
| `cred.bin` | DPAPI 加密后的密码 | **给了也没用** —— 绑定你的机器 + Windows 账号，别人根本解不开 |
| `auto-connect.log` | 运行日志 | **不记录密码**，可以贴出来求助 |

### 别人下载你的程序后会看到什么

**什么都不会看到。** 他第一次双击打开的是配置向导，填的是**他自己的**学号和密码：

```
  auto-connect · 校园网自动认证
-----------------------------------------------------------
还没配置过，先带你配一遍（大约 30 秒）。

学号: 
```

整条链路里没有任何"读取作者账号"的逻辑 —— 程序启动时只会读**本机用户的**
`%APPDATA%\auto-connect\`，那台机器上不存在你的配置。

本项目不联网上报任何数据。
